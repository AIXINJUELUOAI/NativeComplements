# 社区适配与短期任务分支

用于主项目与社区适配的轻量协作约定。已集成的 LOS24 [PR #4](https://github.com/AIXINJUELUOAI/NativeComplements/pull/4) 是差异接入示例。

## 协作保持轻量

- `main` 用于集成和发布；功能、适配、修复使用短期任务分支，必要检查和 Review 后合回，不维护按 ROM 分叉的完整产品。
- 不要求贡献者填模板、补测试报告、录样例或搭建 CI。提交能说明改了什么、针对什么组件即可，现有材料用于审阅，不把材料不足变成逐功能用户警告。
- 保留贡献者作者信息。共同规则与主包由主项目维护，系统专有接入归对应适配者；不能把构建成功当作设备效果已验证。
- 社区可以使用自己的本地测试签名；正式覆盖升级签名只在维护者本地可信发布流程中使用，不提供给 PR。

## 用户看到什么

- 匹配社区适配记录时，仅首次提示一次“当前系统由某某提供适配”，同一记录不会因每次升级反复弹出。
- “关于”中，在开发者下方显示“适配者”；不在首页保留卡片、不罗列能力矩阵、不逐功能提示未适配／未验证。
- “反馈问题”优先路由到已经确认的维护者 Issues 地址；没有确认地址或仓库未开 Issues 时，回主项目，不猜测私人联系方式。LOS24 贡献者为 [LFRon](https://github.com/LFRon)，当前使用主项目反馈入口。
- 未匹配记录不显示“系统不受支持”弹窗，也不因此禁用功能。系统属性只用于信息归属，不授予宿主权限、不决定 Hook 资格。

## 接入的实际边界

遵循“平台事件输入 → 共用规则／状态 → 平台执行与恢复”。相同 Hook 继续共用；真正不同的 Hook 目标、参数布局、安装时机收进对应功能的小目标解析／接入实现。普通业务判断、UID／user／display／锁屏／认证／租约／nonce／恢复保护不为改组而修改。

- 不在业务逻辑中散落 `if Pixel / else LineageOS`，不复制整套功能，不建设通用 ROM 插件平台。
- 只读字段／getter差异优先局部解析；已有宿主文件和 Access／Targets 复用，不增加只有一个实现的接口。
- 可用性以维护者提供的精确接口合同和**实际宿主**必要 Hook 预检、安装结果为依据。失败则对应接入保持原生；未知、尚未启用或尚无回报不当作不支持。
- 管理界面不能代替其他进程扫描 Hook；不因为 ROM 名称、测试资料缺失或未收到结果就关闭功能。Hook 安装成功也不表示视觉、性能和恢复均已实机验证。
- 新增作用域、权限、协议以及认证／电源行为变化仍需审阅，不以适配为由放宽安全边界。
