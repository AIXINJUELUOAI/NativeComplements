# NativeComplements

类原生 Android 功能补全模块。模块名“类原生补全计划”，当前版本为 `0.9.6`（versionCode 83），包含小窗、弹幕通知、来电拦截、边缘防误触、快捷建议、加速度传感器控制与图标适配。

0.9.6 图标单应用页的上传选项改为选择即打开图片选择器：莫奈“上传单色图片”和通知“上传图片”不再需要二次点击；彩色“手动前后景”先打开底部 Sheet，在 Sheet 内选择背景图或透明前景后再打开选择器，页面不再显示两个上传按钮，Sheet 只显示当前是否已选择。来电拦截中开启“拦截全部来电”后，该 SIM 下的号码规则和“添加号码规则”隐藏；规则数据保留，关闭总拦截后恢复显示。

0.9.5 图标适配页移除“基础图标”状态行和分开的 ZIP／文件夹、刷新、移除图标库行，只保留一个“导入图标库”入口；导入时用底部 Sheet 选择 ZIP 或文件夹，刷新移到标题栏，移除图标库放到标题栏更多菜单。逐应用列表改为应用图标 + 名称 + 当前策略 + 箭头，点击进入独立应用页，不再使用弹窗。应用页顶部显示放大的彩色／莫奈／通知预览，下面以整行单选编辑三组策略，上传按钮就地展开，自动保存；应用页通过包名参数使用标准 Activity 返回栈。

0.9.4 来电拦截的号码规则改为每张 SIM 卡片下的独立规则行：点击规则编辑，右侧删除，底部添加；输入弹窗改为系统式单行下划线输入框和 Phone 键盘，单次只编辑一条规则，保留原有 100 条上限与通配符规范化。SIM 2 跟随 SIM 1 时不显示镜像规则，规则只在 SIM 1 下编辑。修复截图后弹幕消失：截图、键盘、系统面板等暂时性 overlay 不再销毁弹幕，而是暂停滚动/隐藏视图，条件恢复后从原进度继续；应用切换或不再 eligible 时才真正隐藏。

0.9.3 弹幕歌词行在正文前加入来源：应用图标、发送者/会话标题和“：”前缀，例如“图标 好友A：你好”。来源图标复用小窗/桌面的 `IconAssets + AppCatalog` 导入图标包结果，未命中或快照未就绪时回退原生图标。模块内新增“弹幕记录”页，保留最近 100 条来源、应用、时间和正文，可清空；弹幕成功显示并写入历史后，使用现有 NotificationListenerService 取消原通知，并忽略这次取消触发的 removed 回调。只有通过原有过滤的已选应用通知才会取消；历史写入失败或弹幕窗口创建失败时保留原通知。这是显示后取消，不阻止通知已产生的提示音、震动或短暂 heads-up；投递前拦截仍未实现。

0.9.2 弹幕通知应用列表在每行左侧显示应用自己的图标，右侧保留开关；首页“弹幕通知”入口改用用户提供的 notes 线性图标，替换原实心聊天气泡。弹幕本体从圆角深色卡片改为参考 Sona“弹幕歌词”的单行样式：无背景、粗体白字、18sp、约 90% 不透明度、30dp 轨道、约 100dp/s 从右向左滚动、进入 120ms 与退出 220ms 淡入淡出；只显示通知正文，正文为空时显示标题。渲染参数参考 Sona 的公开视觉行为，使用本模块自己的 Android View 实现，不复制其源码。

0.9.1 设置界面去掉所有解释性文本和搜索框：页面 Hint、独立介绍段、关于/许可说明、首页标语、解释性行副标题、右上角 `i` 使用说明全部移除，保留控件标题、分组标题、状态/当前值、空状态与错误提示。弹幕通知的应用勾选改为开关，并移除顶部搜索框；加速度传感器控制、图标适配、禁用应用和快捷建议蓝牙弹层的搜索框一并移除。快捷建议页左侧圆形图标改为对应功能色：手电筒和常亮用琥珀色、蓝牙蓝色、验证码青色、链接紫色、地址绿色、按钮显示紫色、以小窗打开蓝色；文字标题保留。

## 图标适配

- 首页进入“图标适配”，选择本地 ZIP 或文件夹。支持 `icons/<包名>/0.png` 背景与 `1.png` 透明前景，允许仓库外壳目录；`themes/<样式>/icons/` 会分开列出，只启用用户选择的一套。也可读取模块 ZIP／MTZ 中名为 `icons` 的内层静态图标 ZIP。
- 图标库只读取 PNG，不执行压缩包里的脚本。模块不内置第三方素材、不提供默认下载地址。缺图、坏图与非标准包名会跳过；多素材库优先级不在本版内。
- 后台导入显示进度并可取消；校验完成后切换不可变素材库。失败或取消保留原库。每层尺寸最大 2048px，允许前后景分辨率不同；各层完整画布映射到同一个自适应图标边界，不裁掉内容或再次缩小留白。
- 开启“启用图标补全”后，逐应用列表仅显示有桌面入口的应用。彩色图标可选择自动、手动前后景、算法补全或不处理。自动优先匹配导入库，未命中保留应用原图，不自动调用算法。仅用户逐应用选择算法后，应用启动时后台生成并缓存；生成前仍保留原图，应用更新后再次启动会更新缓存。真实自适应图标保留已有图层，平面图尝试边缘底色分离并补偿自适应图层缩放；算法不保证语义分层。移除或替换图标库保留逐应用设置和上传图片。
- 莫奈与通知分别提供跟随前景、上传图片、不处理。原生莫奈图层在彩色图标未替换时保持原样。通知另有总开关，默认关闭，逐应用也默认不处理。启用且选择替换后，通知生成保留透明轮廓的单色小图标，避开会话头像、媒体封面和系统状态图。当前替换 StatusBarIconView 使用的状态栏／锁屏／AOD 小图标，展开通知卡片头部仍保持原样。实心或识别失败的图案保留原图。
- 单应用编辑页预览彩色、莫奈、通知三个结果；手动前后景选齐才生效。上传图片在本地转换为 PNG，每张最多 8MiB、2048px；内容寻址保存，选图失败保留上一次设置。
- 系统 Splash 与小窗转场遮罩读取同一彩色缓存。系统 Splash 保留原生布局和动画，不替换应用自己绘制的品牌页面；原生动态图标仍走原生路径。图标库切换不改变窗口任务、焦点或普通应用配置。
- “刷新图标”会逐应用更新 Pixel Launcher 的图标位图缓存，保留图标排列、文件夹和小组件。不清除应用数据，不删除桌面布局数据库。Opticon 卸载后残留的位图也可通过此入口刷新。
- 沿用原有三个 LSPosed 系统作用域，不增加普通应用。更新模块后须由用户重启相关宿主或手机加载新 Hook。桌面主题图标开启时展示莫奈效果，关闭时展示彩色效果；验证时停用其他图标处理。
- 素材通过受 UID 检查的 Provider 提供给桌面、SystemUI 与小窗后端；仅 system UID 可排队触发算法生成。后台只加载当前个人用户有桌面入口且实际需要替换的应用，图层固定至多 256px，纯色背景压为 1px。每宿主像素预算约 96MiB，超额保留原图，不随应用总数降低清晰度。Hook 热路径只读取不可变内存快照并排队，不做磁盘、解码或 Provider I/O。当前不替换工作资料图标。
- 只导入用户选择的文件；ZIP 最多 512MiB、60000 条目，单图最多 8MiB，防止路径穿越和异常展开。导入结果列出成功、缺图跳过及解码失败数。

## 当前小窗实现

- 基于原生 freeform 的默认小窗、mini、小窗与全屏切换，以及关联任务的独立小窗和返回接续。
- 可见 mini 的生命周期与前台输入焦点分开处理；长按菜单提供本应用静音和 mini 大小切换，按钮与图标复用 SunOS 资源。
- 首次新开小窗仅支持横屏的入口横屏，其余默认竖屏；逐用户、应用和页面记忆离场前方向，重新打开同一页面时采用记忆，应用新的明确方向请求优先。mini 收起与展开保留方向，不跟随设备自动旋转改变逻辑画布。记忆最多 512 项，由后端异步持久化，不在 WM 锁内写盘。保留系统栏取色、最近任务恢复与锁屏状态。操作条固定为浅色；普通小窗后方按用户设置压暗，默认 20%，可在“窗口与多任务”调整为 0%～100%。
- 包名打开与原始跳转命中已有任务时，共用目标呈现路径，不重启已有页面；扇区／角落手势对贴边窗先恢复 mini，对 mini 展开默认窗。菜单、通知和链接直接打开默认窗，沿用一个默认窗加一个 mini 的替换规则；包名打开同应用时仍优先保留的主任务。
- 通知发布者与目标应用分别识别。保留原始 PendingIntent 与 fill-in Intent，用其真实 sender Binder 或已经确认的来源任务链绑定目标，兼容代理通知跳转至其他应用；不通过最近任务顺序猜测目标。过期请求、其他用户及无关启动排除；失败沿用未发送时原生发送、已发送时恢复目标的现有逻辑。
- 横屏中的横屏默认小窗缩小 5%，给操作条左右缩小／放大反馈留出空间；触发距离和震动保留。
- 长侧滑转小窗先遮住原生返回的回弹，使用匹配的 Launcher 预览位置接续既有遮罩；无可靠预览位置时直接淡入目标小窗。等待完整 Shell 转场结束，失败或超时恢复显示。仅本次接管后恢复 NORMAL 桌面的原生深度与壁纸缩放；普通返回保留原生动画。实际衔接仍需真机验收。
- “贴边锁屏继续运行”是默认关闭的独立开关；本轮不改变已经验证的运行逻辑。
- 旋转前先隐藏小窗，原生转场结束且位置稳定后淡入；保留 mini 大小、贴边与静音状态，超时释放旋转遮罩。mini 每次物理旋转后回到可用区域右上角；前台应用切换时保留稳态 mini，原生转场结束事务接回小窗缩放、位置与圆角。
- 普通小窗不可自由移动：竖屏固定现有默认位置，横屏固定居左，包括 mini 展开和关联小程序。默认单击空白处关闭，可在“窗口与多任务”开启双击关闭。竖屏底部固定键盘弹出时整体上移，键盘收起后复位；横屏和悬浮键盘不避让。
- mini 拖动关闭目标对齐系统气泡的底部圆环，靠近时真实内容缩小、变淡并吸向圆心，拉出后平滑恢复；进入圆环时触发一次触感反馈，移出后重新进入可再次提示；取消手势不关闭。
- mini 可跟手拖出物理屏幕，约三分之一宽度越界时轻震，松手隐藏为白条；白条距可用屏幕边缘 12dp，触摸区 48×104dp，优先避让返回手势。点击白条恢复 mini，向屏幕内拖动时实时带出内容；长按轻震后可移动白条位置或拖到另一侧，取消手势复原；隐藏保留原应用生命周期、大小与静音状态。
- 只有默认窗避让摄像头挖孔；mini 内容、拖动贴边位置和隐藏白条不预留挖孔区域，横屏按物理屏幕边缘定位，白条仍保留 12dp 间距。竖屏保留状态栏、导航栏避让。
- SystemUI 承载操作层，system_server 管理任务；不依赖无障碍，不要求为普通应用逐个勾选 LSPosed 作用域。

- 原生 WM 保持 freeform，受管理任务发给客户端的配置副本使用非分屏身份，供流媒体应用正常请求横屏；微信专项兼容恢复原生 floating 客户端身份，隔离其标题栏布局与其他应用的方向处理。微信方案尚待真机验收。
- 左右角落通过 SystemUI 现有 InputMonitor 观察原始输入，普通点击与长按直接交给底层应用；斜向滑动达到阈值后才 pilferPointers 并取消底层触摸。Launcher 仅保护对应手势候选流，热区提示窗自身不可触摸。
- “应用间跳转小窗打开”覆盖横竖屏下的分享、链接、文件打开及其他普通跨应用启动，保留原始 Intent、URI 权限和返回结果链。前台应用通过自身 Context 发起的无来源 token 跳转按实际调用身份核对；桌面、最近任务及系统权限、拨号与文件选择器保持原生交互。沿用旧 landscapeShareWindow 偏好键。
- 普通菜单启动直接在最终小窗位置淡入，不经过全屏缩放。普通与 mini 的形态切换、全屏端点和逻辑画布重布局继续用应用图标与底色遮罩承接，收到匹配配置的新绘制后淡出，超时撤除。旋转保留隐藏后淡入。这些动画仍需真机验收。
- 扇区的菜单入口使用横向三个点并固定最下面；已选应用和快捷功能按同一条有序列表显示前 1–5 项（默认 4 项加列表入口）。快捷项使用纯白圆底、黑色图标，选中只放大；扇区数量与列表顺序分开保存，最多 12 项并校验跨进程数据容量。
- 悬浮菜单顶部显示四列、最多三行的混合已选区，应用用应用图标、快捷功能用白圆底黑图标；向下滚动目录时已选区收起，回到顶部重新展开。“应用 / 快捷功能”共用管理模式：加减、长按拖动排序、完成保存；快捷功能目录包含原有八项和新增的应用小窗、自动亮度、省电模式、深色模式，全部默认在库中，用户自行加入。下方应用列表按独立字母标题和四列分组，右侧 A–Z 在向下浏览时显示，回到顶部隐藏，中文按拼音归组；快捷功能按四列网格排列。菜单复用默认竖向应用小窗的尺寸和位置算法，竖屏居中、横屏靠左，背景不压暗，点击空白关闭。
- 应用与快捷功能只在悬浮菜单中修改。设置里的“小窗”直接进入小窗设置页，保留启用开关、手势与菜单、窗口与多任务、小窗触发限制；原小窗管理页和快捷应用页已删除，禁用应用列表保留。

这是一套针对已检查的 Android 17 / API 37 私有接口实现的 LSPosed 适配，并非 SunOS ROM 模式的完整移植。构建、主机检查与真机反馈分别记录，见 [VERIFICATION.md](VERIFICATION.md)。

## 快捷建议

- 独立总开关与分类开关，默认总开关关闭；运行于现有 SystemUI/system 作用域，不增加普通应用作用域或无障碍。
- 设置页将“建议内容”和“按钮与打开方式”分开：前者是手电筒、本次常亮、蓝牙、验证码、链接和地图的图标开关；后者是“按钮显示”和“以小窗打开”。蓝牙、验证码和按钮显示通过底部分组弹层编辑子项，页面本身不再铺开所有滑块和小开关。
- “按钮显示”可调整显示时长 5–300 秒（默认 60 秒）、视觉大小 32–80dp（默认 48dp），小尺寸保留至少 48dp 触摸区，大尺寸多按钮自动换行。长按后跟手拖动到系统气泡样式的底部 X，进入圆环轻震，松手仅隐藏当前提示；拖出圆环松手或取消则恢复，不关闭手电筒、蓝牙或应用。
- 圆形按钮使用桌面应用图标或操作图标，跟随主题、避让手势条与键盘。点击触发系统轻震。应用图标无额外背景；手电筒关闭操作使用深黄色背景、开启操作使用灰色背景，常亮使用浅黄色背景，验证码使用蓝色背景，操作图标使用清楚的对比色。应用／链接／地图成功跳转后消失；验证码开始输入后隐藏，失败时可重试。手电筒开启后关闭按钮在灯亮期间常驻；关闭手电筒后打开按钮按显示时长保留。用户把按钮拖走后，本次亮灯状态不再强制弹回，下一次灯状态变化再恢复。
- CameraManager 真实手电筒状态与 AudioDeviceCallback 蓝牙音频设备连接事件；蓝牙目标从任意可启动应用单选，打开后本次连接不再提示。
- 新短信经 RECEIVE_SMS 运行时权限接收，不读取短信历史；剪贴板识别验证码、十款常用应用链接／口令、地址与地点。仅做本地有界识别，短暂保存在内存中，不记录内容／验证码。
- 验证码默认逐位 100ms，可调 50–500ms，保留前导零。系统侧向用户当前选中的应用窗口发送数字按键，逐次检查窗口对象、UID、键盘、锁屏状态；切换窗口停止。自绘输入框兼容性仍需真机确认。
- 隐藏验证码通知单独开关：仅默认短信应用的非合并、非摘要通知，内容与新收到短信全文一致、且验证码按钮已真正绘制时才取消该条通知；保留 60 秒显示凭据，处理输入完成后才迟到的对应通知。剪贴板候选不触发通知隐藏；不确定时保留原通知，短信接收和保存不变。
- 链接规则覆盖淘宝、京东、拼多多、抖音、快手、哔哩哔哩、小红书、知乎、微博、美团；完整链接交原应用处理，纯口令仅启动应用并保留剪贴板，不声称已经直达商品。地图地址交 geo 搜索，多地图点击选择，地图分享链接保留原 URL。
- 小窗跳转保留整个显式 Intent，以一次性 PendingIntent 复用现有真实启动任务接管链；不退化为仅打开包名首页。关闭此项时全屏打开。手电筒／验证码／常亮不受此项影响。
- 息屏前 DIM 状态下的真实触摸唤亮会按设定显示时长提供“本次常亮”建议。点击后按钮立即消失，仅持有临时 SCREEN_BRIGHT_WAKE_LOCK，不改息屏时长；下次用户熄屏、锁屏、关闭功能或宿主退出即释放。观察失败仅关闭此建议，不影响系统电源流程。
- 通知、输入和 DIM 观察均独立预检接口并隔离失败；APK 与主机检查不代表真机效果通过。

## 边缘防误触

- 首页独立入口，默认关闭。左右可单独启用并调整 1–48dp 宽度、覆盖高度和纵向位置，提供范围预览。新增默认关闭的“显示实际禁触区”，在现有触摸窄窗内按真实尺寸着色，跟随控件避让和暂停规则。
- 透明窄窗消费边缘触点，通过 split touch 保留中央另一触点的路由；实际多指效果待真机确认。固定区域内正常点击也会被屏蔽，不自动识别手掌。
- 独立设置与 UID 检查的只读 Provider，不跟随小窗开关。锁屏、键盘、系统浮层出现时暂停，避让状态栏、导航区和小窗控件热区。
- 不增加无障碍或普通应用作用域。边缘触摸屏蔽与系统返回 InputMonitor 的准入拦截分开处理。

## 来电拦截

- 首页独立设置页，按 SIM 物理卡槽识别双卡；每张卡可拦截全部来电或按号码规则过滤，保持 SIM 数据连接。
- SIM2 可实时跟随 SIM1，关闭跟随后恢复 SIM2 自己的配置。所有拦截选项默认关闭。
- `*` 匹配任意长度，连续星号合并：`952**` 与 `952*` 均匹配 952 开头的号码。未知号码适用单卡全拦，但不匹配号码规则。
- 拦截记录仅存本机，保留最近 200 条并显示 SIM 和原因。应用的电话权限用于显示双卡名称与状态。
- 系统 Hook 在真实来电的 PhoneAccount → SubscriptionInfo → 卡槽链路上判定，通过 Telecom 原有过滤结果执行挂断与通话日志，不占用默认拨号或来电识别应用角色。紧急回拨等原生紧急场景维持平台处理。
- 本轮接口依据设备 Android 17 的 `service-telecom.jar` 核对，运行于现有 `system` 作用域，无新增普通应用作用域。设置页显示后端最近运行时间；实际来电效果仍需真机验收。

SIM2 服务闪动的现场日志已采集，出现 IMS 注册超时及同一波断链中的无效数据承载响应，关闭拦截后仍持续。采样开始时故障已经存在，日志中也未见实际拦截命中，尚未确定最初触发原因。preview6 保留平台已经阻断或忽略的原始来电结果，避免模块覆盖其原因和处理方式；设置页的配置／心跳刷新不再重复读取 SIM 列表，仅在订阅变化、权限变化或页面恢复时更新 SIM 信息。新增仅在配置变化时输出的开关、规则数量和时间诊断，并展开异常根类型与栈位置，不记录号码或异常原始消息。这些调整不等于 SIM2 闪动已修复；本版未修改 radio、SIM 或数据连接逻辑。

## 环境与构建

- JDK 17+、Android SDK `android-37.0`，Gradle Wrapper 8.14.4。
- SDK 路径通过 `ANDROID_HOME` 或本地 `local.properties` 配置。
- 覆盖升级沿用本机 `.local/demo.keystore`；该文件不进入 Git，新的工作目录需要在本地配置原签名。

Windows 下执行：

```powershell
.\gradlew.bat --no-daemon --console=plain :app:assembleRelease
```

构建、检查包身份和签名并交付 APK：

```powershell
python tests/package_release.py
```

产物位于 `deliverables/NativeComplements-<version>.apk`。脚本只生成 APK，不生成源码 ZIP、备份或验收报告，不安装应用、不操作设备。

## LSPosed 作用域

固定三个作用域：

- `system`
- `com.android.systemui`
- `com.google.android.apps.nexuslauncher`

应用 ID 为 `dev.nativecomplements.module`（0.6.0 起，源码包路径仍为 `dev.local.sunwindowdemo`），宿主协议为 16。安装和重启由用户自行安排。

## 项目结构

- `app/src/main/java/dev/local/sunwindowdemo/home`、`navigation`、`core/ui`：首页、导航和共用界面。
- `features/floatingwindow/config`、`features/floatingwindow/ui`：小窗配置与设置页。
- `features/callblocking`：电话设置、规则、记录、受 UID 限制的 Provider 与独立系统 Telecom Hook。
- `features/floatingwindow/legacy`：当前系统 Hook、任务管理、窗口呈现和输入处理。
- `tests`：主机检查、归档接口签名和打包工具。
- `baseline`：不可变 Demo8.2 来源、摘要和历史构建证据。

`python tests/verify_runtime.py` 检查 Demo8.2 来源、变更登记及主机规则；`python tests/verify_target.py` 检查归档目标的一部分接口签名，后者不代表当前设备完整兼容性。

## 开发约定

以 `main` 集成，已交付版本使用 tag 固定。并行功能各用独立分支和 worktree；系统 Hook 入口、共用配置、首页导航与版本号统一集成。运行代码相对 Demo8.2 的变更原因记入 `tests/runtime-changes.json`。

日志、构建缓存、设备采集、签名和交付文件不提交；源码通过 Git 版本管理，不创建逐轮目录副本。
